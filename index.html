Design system — documentation

dis-system

Rational-brutalist components for technical products.

Vanilla HTML/CSS/JS, designed in Figma, every value traced to a design token. Built for developers and agents first; nothing here is decorative without a functional reason.

Primitives

Live token reference: every sample is drawn from the same --ds-* custom properties in tokens/output.css that the components consume, resolved for the current theme.

Colors

Raw palette, the same in both themes. Accent carries meaning only: primary marks what can be clicked, secondary and tertiary tell categories apart, and each light tint is a background for its accent. Neutral is the structure (text, surfaces, rules), warm at the pale end so a filled area reads as paper rather than a screen. System colors say status (success, warning, error) and nothing else: strong for text and icons, medium for fills, light for row and panel backgrounds.

Typography

One family, Inter, so hierarchy is carried by size and weight alone. The large headings are set in regular weight because their size already makes them stand out; medium weight marks the smaller headings and emphasis. The two link styles say what a click does: a solid underline leaves the page, a dotted one stays on it. Captions are small uppercase labels for data.

Spacing

A small fixed scale, so gaps between elements repeat and alignment can be checked by eye. cell (10px) and row (44px) are the table and list rhythm; row is also the minimum touch-target height.

Shadow

Three depth steps, each a hard, unblurred edge rather than an atmospheric effect: flat for surfaces that sit in the page, tief-1 (a one-pixel bevel, light top-left, dark bottom-right) for anything lifted off it such as cards and buttons, tief-2 (the dark edge doubled) for what floats over other content, like toasts and tooltips.

Icons

One 24px grid, drawn from squares, triangles and circles only, so every icon reads at a glance and none carries decoration. Grey marks controls that act on the view (drag, sort, close, add, filter), blue marks state (selection, loading, the active theme), and the ochre dot is the one alert color. Every file in icons/ is drawn in currentColor, so hover, selection and dark mode recolor it from the theme's tokens.

Components

One card per component family, in the order of the Figma D_SYSTEM web-view page. Each card shows a representative set; Show all components opens the generated previews of every component in that family (scripts/build_manifest.py, from each meta.json's category).

Buttons

A button is text in the accent color, and its underline says what a click does: solid leaves the page, dotted stays on it. An icon is added only when it names the action faster than the word; on its own it needs a spoken name. The outline marks a button as a separate control when it sits among other text rather than in a toolbar or table row.

Tags

A tag names a category or a status in one word, and its color says which family it belongs to: the three accents for categories, green, yellow and red for how something went, neutral for a plain mark. Active is the solid form for a single tag that has to stand out; Passive keeps the same hue at a lighter weight for rows of many tags.

Inputs

A field is either transparent, when it sits inside a row or a toolbar that already frames it, or filled, when it stands alone on a surface and has to show where you can type. A dropdown is the same field with an arrow: the arrow is the only thing that says the value is picked, not typed.

Toasters and tooltips

A toast reports the result of something you just did: its fill says how it went (green for done, yellow for a warning, red for a failure), it goes away by itself, and the square cross closes it sooner. A tooltip explains the control you are pointing at, dark so it reads as a layer above the page in either theme, and only while you point at it or focus it.

Tables

The tabs show the same records at three data loads: a minimal preview with only name, status and actions, a middle load, and the full table. Pick the lightest one that still answers the question the page is for. Rows are one line tall and ruled only below, so the eye runs along a record rather than down a grid of boxes. Color is kept for status alone; links, actions and editable notes keep the accent and underline conventions of the buttons, so a cell that can be clicked looks like everything else that can be clicked.

Navigation

One bar across the top of every page: where you are on the left, the pages in the middle with the current one in bold, and view settings such as the theme on the right. It stays in place while the page scrolls, so the way out is always visible.

Sidebar

A list of sets beside the content it filters. The selected set is filled rather than colored, so the accent stays free for what can be clicked; the bookmark marks a saved set; the arrow folds the list to a narrow strip when the content needs the width.

Cards layouts

Images keep the proportion of what they show (landscape, portrait, square) at one fixed height, so a row of mixed work lines up without cropping. Where there is nothing to show yet, the space is held by a quiet placeholder that says what will appear there instead of leaving a hole.

Controls

A choice between a few options is a radio group of text buttons, so each option reads as something to click and the ring shows which one is on. Several images to pick from sit in a single scrolling strip with a visible scrollbar, so it is clear there is more beyond the edge.

Popups

A popup takes over the page only for a decision that has to be made before going on; the dimmed backdrop says the rest of the page is out of reach until then. Three widths for three amounts of content: small for a short confirmation, medium for a form or a summary, big for wide content. The main action is the bold button on the right.
